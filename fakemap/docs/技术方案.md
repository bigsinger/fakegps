# FakeMap 技术方案

## 1. 目标与边界

本次重构将旧项目从“全局改写位置 getter 与设备环境”的方式迁移为两层架构：

1. 公开、可审计的系统标准模拟位置作为主引擎；
2. Xposed 只作为显式作用域内的应用兼容层。

安全边界是：不隐藏 Mock 标记，不修改系统完整性或反滥用信号，不 Hook `system_server` 私有实现，不伪造 Wi-Fi、蜂窝、SIM、GNSS/NMEA 或原始测量。

## 2. 现代模拟位置方法

### 2.1 系统 Test Provider

Android 6～11 使用公开的 `LocationManager.addTestProvider` 旧签名；Android 12 及以上使用 `ProviderProperties` 新签名。服务同时尝试 GPS 和 Network Provider，每秒创建新的 `Location` 并更新时间、elapsed realtime、精度、海拔、速度与方向。

Android 12 及以上通过公开 API 设置 Mock 属性，低版本由 Test Provider 语义标记。连续三轮所有 Provider 都拒绝更新时，服务主动回滚并报告失败，避免通知显示“运行”而实际没有投递。

参考：

- [LocationManager API](https://developer.android.com/reference/android/location/LocationManager)
- [Location API](https://developer.android.com/reference/android/location/Location)
- [Android 后台定位与前台服务](https://developer.android.com/develop/sensors-and-location/location/permissions)

调研同时评估了 Google Play services 的 `FusedLocationProviderClient.setMockMode/setMockLocation`。它适合已经依赖 GMS 的单一测试应用，但不是系统级通道，许多国内设备也没有 GMS，因此本项目不直接打包该客户端。FakeMap 选择 Android 公共 Test Provider 作为跨 Android 6～17 的主引擎；目标应用中的 GMS `LocationResult` 与一次性 Fused `Task<Location>` 再由按应用兼容层处理。

- [FusedLocationProviderClient Mock API](https://developers.google.com/android/reference/com/google/android/gms/location/FusedLocationProviderClient)

### 2.2 生命周期

- 前台服务为 `START_NOT_STICKY`，进程重建不会伪报旧状态。
- 安装 Provider 后立即记入回滚集合；enable 或后续步骤失败会马上移除。
- 停止、销毁或异常时均禁用并移除 Test Provider。
- Android 12 的近似位置权限可以启动定位前台服务；应用不读取真实坐标。
- Android 15 及以上合并系统栏与刘海 Insets，避免 target 37 强制 edge-to-edge 遮挡控件；旧系统布局不变。

## 3. Xposed 双构建

### 3.1 legacy

legacy APK 使用 Xposed API 89 与 `assets/xposed_init`，保留 `xposedsharedprefs` 和默认作用域元数据。

配置文件只包含坐标与目标白名单。模块应用尝试使用 New XSharedPreferences 约定的 `MODE_WORLD_READABLE` 调用：LSPosed、EdXposed、Vector 等实现会把调用重定向到框架安全区；未实现安全区且系统禁止该模式时捕获异常并退回私有文件，Hook 侧因此读取不到配置并失败关闭。地图 Key 等凭据永远不进入该文件。

Android 6 原版 Xposed 可使用传统 XSharedPreferences。原版 Xposed 在 Android 7/8 没有现代安全偏好通道时不承诺可用，应改用系统标准模式或支持 New XSharedPreferences 的框架。

### 3.2 modern

modern APK 最低 Android 8.1，使用 libxposed API 102 的 `META-INF/xposed` 入口与 `io.github.libxposed:service`。

- 目标进程先检查框架的 `PROP_CAP_REMOTE`。
- Hook 侧通过 `getRemotePreferences` 读取框架拥有的只读偏好。
- 模块应用通过 Xposed service listener 获取远程能力，并用同步 `commit` 写同名组。
- modern manifest 用带 UID 与 Binder descriptor 校验的 Provider 替换 service AAR 默认入口，只接受 root 或 system UID 传入框架 Binder。
- 服务死亡会移除连接；重新绑定时自动用本地配置覆盖同步。
- 偏好 listener 使缓存立即失效，同时保留一秒轮询兜底。

这避免了 Android 11 包可见性导致任意目标应用无法解析模块 ContentProvider 的问题，也不需要 `QUERY_ALL_PACKAGES`。

参考：

- [libxposed API](https://github.com/libxposed/api)
- [libxposed service](https://github.com/libxposed/service)
- [现代 Xposed 模块结构](https://github.com/LSPosed/LSPosed/wiki/Develop-Xposed-Modules-Using-Modern-Xposed-API)

### 3.3 Hook 面

模块在应用 `Application.attach` 之后安装公开 API Hook：

- `LocationManager.getLastKnownLocation`；
- 请求注册时发现的 `LocationListener` 或 Consumer 回调；
- Intent/Bundle 标准位置字段；
- 目标应用已有的 `com.google.android.gms.location.LocationResult` 公共 getter。
- GMS Fused Location 的一次性 `Task<Location>`、`getResult` 与 `OnSuccessListener` 公共回调边界。

原方法抛出的异常保持不变。legacy after hook 会先检查 `hasThrowable()`；modern hook 先执行 `chain.proceed()`，不会把权限异常替换成模拟结果。

运行时每次交付都重新检查：配置有效、开关启用、当前包名在白名单。框架作用域是第一层，应用白名单是第二层。

多包共享进程只按框架报告的首个应用包建立配置身份；非首包回调不安装第二套 Hook。这样不会因回调顺序把另一个共享 UID 包误当作授权目标。需要测试共享进程时，应把首包作为明确目标并理解 Hook 会作用于整个进程。

## 4. Android 版本策略

项目使用 `minSdk 23`、`compileSdk 37`、`targetSdk 37`。modern flavor 因 libxposed 运行环境要求覆盖为 `minSdk 27`。

Android 17 的编译配置遵循官方 SDK 指南，构建工具使用支持 API 37 的 AGP 9.3。行为变更按官方清单核对，运行时仍需在 Android 17 设备上做框架级回归。

- [Android 17 SDK 配置](https://developer.android.com/about/versions/17/setup-sdk)
- [Android 17 行为变更](https://developer.android.com/about/versions/17/behavior-changes-17)
- [AGP 与 API 级别兼容表](https://developer.android.com/build/releases/about-agp)

## 5. 地图方案

### 5.1 选择结果

没有把高德、百度和 Google 三套大型原生 SDK 同时打包。当前方案为：

- 国内：中国大陆目标点可用高德 JavaScript API 2.0，运行时使用开发者自己的 Key 与安全密钥；
- 国际：本地 Leaflet 1.9.4 客户端连接 HTTPS 栅格服务；
- 自动：根据目标点是否处于 GCJ-02 工程掩码及高德凭据是否完整选择；
- 回退：高德脚本、鉴权或初始化超过 12 秒后切换国际地图。

优势是 APK 无本地 SO、没有 ABI 分裂、没有硬编码商业 Key、国内外可分别选择合规服务。代价是地图需要网络，生产瓦片和高德额度由部署者负责。

### 5.2 坐标

持久化坐标始终为 WGS-84。高德显示前执行 WGS-84→GCJ-02，选点回传后迭代转换回 WGS-84。转换只在工程掩码内执行，避免旧式大矩形把 Kathmandu、首尔、乌兰巴托等境外点错误偏移；逆变换在首次区域判定后冻结迭代路径，避免边界附近反复切换。

掩码来自 Natural Earth 1:10m Admin-0 中国几何（上游提交 `ca96624a56bd078437bca8184e78163e5039ad19`，公有领域），保留该中国要素的全部 70 个离散组件，以保持拓扑的 `0.03°` 容差离线简化，并仅对大陆、海南之外的离散小岛使用 `0.015°` 工程容差，以覆盖数据比例尺遗漏的近岸小岛而不向境外国境扩张；香港、澳门和台湾要素显式排除。它用于地图工程分类而非法律边界，边境、岛屿和海域等敏感位置仍须人工核验。瑞丽、腾冲、景洪、河口、亚东、塔城、厦门、舟山、平潭、崇明及周边地区已加入回归测试。

### 5.3 WebView 安全

- 本地 HTML 从固定的虚拟 HTTPS 主机加载。
- 不使用 `addJavascriptInterface`；页面通过只允许主文档处理的 `fakemap://bridge` 协议回传白名单事件。
- CSP 禁止 iframe、object、base 和 form，远程脚本只开放高德所需域。
- 禁止 file/content access、WebView geolocation、混合内容和自动窗口。
- 两种 `shouldOverrideUrlLoading` 重载共用校验，覆盖 Android 6。
- 外部版权链接在系统浏览器打开，未知导航被拒绝。
- TLS 证书错误直接取消，界面不显示可能含 Key 的原始错误 URL。
- 页面使用 `strict-origin-when-cross-origin`，使公共瓦片请求保留服务条款要求的来源信息。

### 5.4 版权

地图 WebView 在上下原生区域之间独占布局空间，Leaflet attribution、高德 Logo、版权和审图信息不会被按钮覆盖。自定义栅格配置把 URL、署名文字和许可 URL 作为一组保存，页面使用 DOM 转义生成链接，不接受任意署名 HTML。

参考：

- [高德 JavaScript API 2.0](https://lbs.amap.com/api/javascript-api-v2/summary)
- [高德安全密钥说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)
- [高德世界地图](https://lbs.amap.com/api/javascript-api-v2/guide/map/world-map)
- [Leaflet](https://leafletjs.com/)

## 6. 隐私和供应链

- 删除旧版 Bugly、百度定位、Google Maps、Material、AndroidX 和动态 `latest.*` 依赖。
- 地图凭据与 Xposed 共享配置分库；共享库没有账号、Key、token 或签名信息。
- `allowBackup=false`，并在 Android 12+ 数据提取规则中排除全部存储域。
- 网络安全配置只信任系统 CA，禁止明文流量。
- Leaflet 静态文件和许可证随 APK 打包；Xposed 与 libxposed API 为编译期或框架接口。
- release 使用 R8 和资源压缩。

## 7. 已知限制

- 没有网络时只能手工输入坐标。
- 公共 OSM 瓦片没有可用性保证；生产环境必须配置有授权的服务。
- 高德模式是开发者自备 Key 方案，不启用世界地图；生产分发必须使用高德安全代理或合规的原生 SDK 方案。
- Xposed 的实际兼容性由框架版本、ROM 和作用域策略共同决定。
- 应用不模拟路线、传感器、GNSS 原始测量或卫星状态。
- Xposed 兼容层不改写 HMS、高德等厂商自定义 Location 类型；这类应用优先使用系统标准模式并按厂商 SDK 单独回归。
- Android 17 上的 modern Xposed 需要框架本身支持该系统；应用可以编译和安装并不代表任意旧框架可以运行。
