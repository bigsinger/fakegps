# 构建与测试

## 1. 工具版本

| 组件 | 版本 |
| --- | --- |
| JDK | 17 或更高；建议使用 JDK 17 |
| Android SDK Platform | 37 |
| Android Build Tools | 37.0.0 |
| Android Gradle Plugin | 9.3.0 |
| Gradle Wrapper | 9.5.1 |
| Java 源码级别 | 11 |

AGP 9.x 不能在 JDK 11 下运行。执行 Gradle 前应确认 `JAVA_HOME` 指向 JDK 17，并用 `java -version` 验证。不要把本机绝对 JDK 或 SDK 路径提交到仓库。

项目明确设置 `android.builtInKotlin=false` 和 `android.useAndroidX=false`，源码与运行依赖均不使用 Kotlin 或 AndroidX。libxposed service 只依赖其 Java Binder interface。

## 2. 镜像

- Android/Google、Maven Central 和 Gradle 插件依赖优先使用阿里云镜像，官方仓库作为回退。
- Gradle Wrapper 使用腾讯云 Gradle 镜像。

首次构建需要下载依赖。离线环境应提前准备 Gradle、Android SDK Platform 37 和缓存依赖，不要把本机缓存目录提交到仓库。

## 3. 构建命令

Windows：

```powershell
.\gradlew.bat clean test lintLegacyRelease lintModernRelease assembleLegacyRelease assembleModernRelease
```

Linux/macOS：

```bash
./gradlew clean test lintLegacyRelease lintModernRelease assembleLegacyRelease assembleModernRelease
```

AGP 9 只为当前配置生成 debug 单元测试任务，根任务 `test` 会运行 `legacyDebug` 与 `modernDebug` 两组相同业务测试。release 代码另由双 flavor Java 编译、lint、R8 和 assemble 验证。

## 4. 产物

```text
release/FakeMap-release-2.0.0-legacy.apk
release/FakeMap-release-2.0.0-modern.apk
```

Gradle 仍会在 `app/build/outputs/apk` 保存中间输出；`assembleLegacyRelease` 和 `assembleModernRelease` 会把最终签名 APK 自动复制到根目录的 `release`。项目没有 `.so`，APK 的 DEX 与资源在 arm64-v8a 和 armeabi-v7a 上完全相同，因此只生成通用 release APK，不生成无意义的 x86 或 ABI 分包。

## 5. 签名

仓库包含专用测试签名和 `signing.properties`，仅用于本项目调试、覆盖安装和自动化测试。不得把它用于应用商店或生产分发，也不要在同一签名中加入个人或组织身份信息。

正式发布时应在安全环境替换签名配置，并确保新的凭据不提交到公共仓库。

## 6. 自动测试

当前单元测试覆盖：

- WGS-84/GCJ-02 北京往返；
- London、Kathmandu、Seoul、Ulaanbaatar 不转换；
- 海南、深圳进入 GCJ-02 工程掩码；
- 国内外自动地图选择及凭据回退；
- 目标包名解析、格式化与系统包保护；
- 位置配置数值校验和方向归一化。

执行：

```powershell
.\gradlew.bat test
```

静态检查：

```powershell
.\gradlew.bat lintLegacyRelease lintModernRelease
```

## 7. 模拟器验证

设备连接后：

```powershell
adb devices
adb install -r release/FakeMap-release-2.0.0-legacy.apk
adb shell am start -n com.bigsing.fakemap/.ui.MainActivity
```

测试标准模拟位置时，可在测试设备开发者选项中手工选择 FakeMap；自动化实验设备也可使用受控的 AppOps 命令。不要在非测试设备上修改 AppOps。

建议核对：

1. 首页、帮助页和地图页无崩溃；
2. 地图缩放控件和右下版权始终可见；
3. 开始后通知出现，停止后 Test Provider 被移除；
4. `dumpsys location` 不再保留停止后的测试 Provider；
5. 无权限时显示错误而不是伪报运行；
6. 覆盖安装 modern APK 后正常启动；
7. APK 内没有原生库、AndroidX 类、硬编码地图 Key 或旧版地图 SDK。

普通 Android 模拟器不能验证 Xposed Hook。legacy/modern 框架功能必须在已安装对应框架的专用测试设备上验证。

## 8. 发布前检查

```powershell
git diff --check
git status --short
```

并确认：

- 所有 Markdown 为 LF；
- 没有本机名、账号、路径、姓名、电话或邮箱；
- 没有真实地图 Key、token 或生产签名；
- 两个 release APK 均通过签名验证；
- Git 只保留 `main` 分支并已推送。
