# FakeMap 使用帮助

## 1. 安装前选择版本

- Android 6～8.0，或使用 EdXposed、LSPosed/Vector legacy 接口时，安装 `legacy` APK。原版 Xposed 的配置通道只在 Android 6 明确支持。
- Android 8.1 及以上且框架明确支持 libxposed API 101/102 时，安装 `modern` APK。
- 不使用 Xposed 时，两种 APK 都可运行系统标准模拟；Android 6～8.0 只能安装 `legacy`。

两个 APK 使用相同包名和签名，不能同时安装。切换版本可直接覆盖安装；正式使用前建议先停止模拟服务。

## 2. 配置坐标

FakeMap 内部统一使用 WGS-84：

1. 在首页输入纬度和经度；纬度范围为 `-90～90`，经度范围为 `-180～180`。
2. 根据需要填写精度、海拔、速度和方向。速度单位为米/秒，方向会归一化为 `0～360` 度。
3. 也可以点击“在地图上选点”，点击地图后选择“使用此位置”。
4. 点击“保存位置和作用域”。

输入框接受小数点或小数逗号。坐标文本和通知始终采用无歧义的技术格式显示。

## 3. 系统标准模拟模式

这是首选方案，适合应用开发、自动化测试和一般设备测试，不需要 Root 或 Xposed。

1. 打开 Android 开发者选项。
2. 找到“选择模拟位置信息应用”或同义设置，选择 FakeMap。
3. 回到 FakeMap，允许精确或近似位置权限。该权限用于 Android 的定位前台服务；FakeMap 不读取真实位置。
4. 点击“开始模拟”。通知栏会显示持续运行状态。
5. 在待测应用中验证位置。
6. 测试完成后点击“停止模拟”。应用会禁用并移除已安装的测试 Provider。

如果系统提示“尚未把 FakeMap 选为模拟位置信息应用”，请重新检查开发者选项。部分 OEM 在省电或后台限制后会终止服务，需要将 FakeMap 设为允许后台运行。

Android 会保留官方 Mock 标记，这是标准接口的预期行为。FakeMap 不提供隐藏标记的选项。

## 4. Xposed 按应用模式

Xposed 模式用于待测应用没有正确消费系统 Test Provider，或需要在单个应用的公开位置交付边界做兼容测试的场景。

### 4.1 配置框架作用域

1. 在 Xposed 管理器中启用 FakeMap 模块。
2. 把 FakeMap 自身加入作用域，以便 legacy 安全偏好或 modern 服务完成配置同步。
3. 把每个待测第三方应用加入作用域。
4. 重启作用域应用；框架要求时重启设备。

不要把 Android 系统、系统界面、定位服务或 Google Play 服务加入作用域。FakeMap 也会在代码中拒绝这些包。

### 4.2 配置应用白名单

1. 在 FakeMap 的“目标应用包名”中每行填写一个完整包名，例如 `com.example.testapp`。
2. 开启“启用位置替换”。
3. 保存配置。
4. 强行停止并重新打开新加入的目标应用。

只有“框架作用域”和“FakeMap 白名单”同时命中时才会替换位置。配置损坏、框架远程能力缺失或包名不匹配时会保持原位置。

modern 构建若显示“尚未连接”，请先在框架中启用模块并重新打开 FakeMap。配置会在服务连接时自动同步。

原版 Xposed 在 Android 7/8 没有 New XSharedPreferences 安全通道，FakeMap 会失败关闭而不暴露私有配置；这两个系统请使用标准模式或明确支持该通道的框架。

### 4.3 替换范围

FakeMap 只处理公开交付边界：

- `LocationManager` 的最近位置结果；
- `LocationListener` 和公开 Consumer 回调；
- Intent/Bundle 中的标准位置字段；
- 应用已集成的 Google `LocationResult` 公共 getter。
- GMS Fused Location 一次性 `Task<Location>` 的结果与成功回调。

FakeMap 不 Hook `Location` 基础 getter，不修改 Wi-Fi、基站、SIM、GNSS/NMEA、系统设置或隐藏 API，也不会注入 `system_server`。

HMS、高德等厂商自定义位置对象不在 Xposed 替换范围内；遇到这类 SDK 时优先使用系统标准模式，并在对应厂商环境单独验证。

## 5. 地图选点

### 5.1 自动模式

- 目标点处于高德 GCJ-02 工程适用区域，且同时配置了高德 Web Key 和 JS 安全密钥时，优先使用高德。
- 目标点在境外、凭据不完整或高德加载失败时，使用国际栅格地图。
- 自动判断依据目标坐标，不使用 SIM 国家、运营商或系统语言。

边境和海域坐标建议人工切换 Provider 并与权威坐标核验。

### 5.2 国内高德地图

1. 在高德开放平台创建 JavaScript API 2.0 的 Web Key。
2. 按高德要求配置 `securityJsCode`、域名限制和配额。
3. 在 FakeMap 中填写 Key 与 JS 安全密钥。
4. 选择“自动”或“高德地图 JS API”。目标点不在中国大陆时，即使显式选择高德也会回退国际地图。

高德脚本加载超过 12 秒、鉴权失败或地图未完成初始化时，会在当前会话回退国际地图。本项目不启用需要额外授权的高德世界地图能力。

当前高德入口是开发者自备 Key（BYO Key）模式。Key 和安全密钥不会写入代码或 Xposed 共享配置，但会保存在本机应用私有存储中，并会按高德 JS API 要求进入页面运行环境。高德不建议生产环境明文使用 `securityJsCode`；正式分发应改用官方 `serviceHost` 安全代理或可绑定包名与签名的原生 SDK。Root/Xposed 环境不应被视为能抵抗设备管理员的秘密保险箱。

### 5.3 国际栅格地图

项目内置 Leaflet 客户端，默认连接 OpenStreetMap 公共瓦片端点。公共端点只适合轻量开发测试，没有 SLA，不应作为生产 CDN。

如使用其他有授权的 HTTPS 栅格服务，必须同时填写：

- 包含 `{z}`、`{x}`、`{y}` 的 HTTPS 瓦片 URL；
- 数据署名文字；
- 对应的 HTTPS 许可或版权链接。

请遵守服务商的缓存、速率、Logo、署名和商业使用条款。FakeMap 不预取瓦片，也不会在地图版权区上方覆盖按钮或卡片。

## 6. 常见问题

### 目标应用位置没有变化

- 标准模式：确认开发者选项已选择 FakeMap，通知栏显示服务运行，待测应用确实使用 Android 位置服务。
- Xposed 模式：确认 APK 类型匹配框架，FakeMap 和目标应用都在框架作用域，目标包名完全一致，并已强行停止后重开目标应用。
- modern 模式：确认首页显示框架服务已连接或入口已激活。

### 地图没有显示

- 检查网络、TLS 代理、WebView 版本和服务配额。
- 高德必须同时填写 Key 与 JS 安全密钥。
- 自定义瓦片地址必须是 HTTPS，并包含三个模板变量。
- 公共 OSM 服务可能限流；请等待或切换到有授权的瓦片服务。

### 为什么仍能检测到 Mock

这是设计目标。Android 12 以后提供公开的 `Location.isMock()`，FakeMap 生成的位置会保留 Mock 属性。该工具用于可审计测试，不用于欺骗风控、游戏、考勤或内容地域限制。

### 如何卸载

先在 FakeMap 中停止模拟，再在 Xposed 管理器中停用模块并重启相关应用，最后卸载 APK。
